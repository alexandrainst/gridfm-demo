# 12. Glossary

The glossary defines the project's own terms, the Flower terms the documentation relies
on and the power grid terms the data uses. The documentation uses these terms as defined
here.

| Term            | Definition                                                                                                                                                                                                                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ADR             | Architecture decision record. A record, in the architecture decisions section, of a decision, its context, alternatives and consequences.                                                                                                                                                              |
| Bus             | A node of a power grid, such as a substation. gridfm-graphkit predicts the voltage and power at each bus of a scenario.                                                                                                                                                                                |
| Client          | One participant of a federation, with its own data, SuperNode and ClientApp. Numbered from 0 by its client ID, which must not change after the first run.                                                                                                                                              |
| Client ID       | The number that identifies a client, set as `client-id` in its node config. Experiments use it, for example to seed training.                                                                                                                                                                          |
| ClientApp       | Flower's short-lived client process, which runs the FAB's client side next to a SuperNode. One container per client.                                                                                                                                                                                   |
| Experiment      | A training procedure: the model, its gridfm-graphkit configuration and the server and client code. A package in `flower_app/experiments/`, chosen by name.                                                                                                                                             |
| FAB             | Flower App Bundle. The archive of `flower_app/` that `flwr run` ships to the ServerApp and ClientApps with each run. It carries only `*.py`, `*.toml` and `*.md` files.                                                                                                                                |
| Federation      | A set of clients with their synthetic data, and the Flower infrastructure that connects them to the server. Its definition is a folder in `federations/`, and the containers Docker Compose starts from it are the running federation. Flower uses the word for the SuperLink and its SuperNodes only. |
| gridfm-datakit  | The GridFM project's Python library that generates synthetic grid scenarios from a config. Used on the host by `gridfm data`.                                                                                                                                                                          |
| gridfm-graphkit | The GridFM project's Python library of graph neural network power flow models. Used in the ClientApps and on the host by `gridfm predict`.                                                                                                                                                             |
| Isolation mode  | Flower's setting for where apps run. The demo uses `process`, in which the ServerApp and ClientApps run in their own containers.                                                                                                                                                                       |
| Lightning       | The deep learning framework whose trainer each client uses. gridfm-graphkit's tasks are Lightning modules.                                                                                                                                                                                             |
| MATPOWER        | A power system file format. The scripts build custom grids in its case format.                                                                                                                                                                                                                         |
| Network         | A grid topology that gridfm-datakit generates scenarios for. A client's data holds one subfolder per network. Also called a grid or a case. Neither the Docker network `flwr-network` nor the neural network.                                                                                          |
| Node config     | The settings Flower gives one SuperNode, set in the Compose file. It names the client's ID, data directory, networks and scenario counts.                                                                                                                                                              |
| Power flow      | The computation of the voltages and power flows of a grid for a given load and generation. The model learns to predict its solution.                                                                                                                                                                   |
| Prediction      | The model's output for every scenario of a client, written by `gridfm predict` to `predictions/` as one Parquet file per client.                                                                                                                                                                       |
| Run             | One execution of an experiment on a federation. Its outputs are in `outputs/<federation>/<experiment>/<timestamp>/`, and the gridfm CLI names it `<experiment>/<timestamp>`.                                                                                                                           |
| Run config      | The settings Flower passes to one run. Its defaults are in `[tool.flwr.app.config]` of `pyproject.toml`, and it names the experiment.                                                                                                                                                                  |
| Scenario        | One load and topology case of a network, with its power flow solution. gridfm-datakit generates them, and a client uses at most the number its node config sets.                                                                                                                                       |
| ServerApp       | Flower's short-lived server process, which runs the FAB's server side next to the SuperLink. One container per federation.                                                                                                                                                                             |
| SuperLink       | Flower's long-running server, which accepts runs and routes messages between the ServerApp and the SuperNodes.                                                                                                                                                                                         |
| SuperNode       | Flower's long-running client process, which connects to the SuperLink and holds the node config. One container per client.                                                                                                                                                                             |
